# Как менять блок «Со стройплощадки»

[← Вернуться к списку инструкций](README.md)

## Что изменяет эта инструкция

Блок **«Со стройплощадки»** показывает фотографии реальных этапов строительства: сборку каркаса, монтаж кровли, отделку и другие работы. Фотографии переключаются стрелками и автоматически через несколько секунд.

Это отдельный фотоотчёт. Он не обновляет блок «Проекты в работе» и не берёт из него данные автоматически.

## Где находятся текст и фотографии

- Список публикаций: `content/construction-updates.json`.
- Фотографии: `assets/construction/`.

Каждой новой фотографии давайте своё понятное имя:

```text
assets/construction/skt-82-frame-medvedevo.webp
assets/construction/skt-82-roof-medvedevo.webp
```

Название пишите маленькими латинскими буквами, без пробелов. Слова разделяйте дефисами.

В JSON путь пишется с прямыми слэшами `/`. Не вставляйте путь с диском (`C:\...`), обратные слэши (`\`) или первый слэш перед `assets`.

## Как подготовить фотографию

Для фотографий со стройплощадки:

- рекомендуемый размер — **1448 × 1086 пикселей**;
- пропорции — **4:3**, горизонтальный прямоугольник;
- лучший формат — **WebP**;
- можно использовать JPEG (`.jpg`);
- рекомендуемый вес — **до 500 КБ**.

На разных экранах рамка имеет разную форму, поэтому сайт заполняет её фотографией и немного обрезает края. Главную часть работ располагайте ближе к центру.

В правом верхнем углу находятся стрелки переключения. Внизу находится тёмная подпись. Не размещайте важные детали, лица и текст у верхнего правого и нижнего краёв.

Не публикуйте фотографию, если на ней видны личные данные, номера документов, номера телефонов, адресные таблички без разрешения, лица людей без их согласия или опасная ситуация на стройке.

Поле `alt` кратко описывает именно то, что видно, например: `Монтаж стропил на каркасном доме в Медведево`.

## Что означают поля

| Поле | Что писать |
| --- | --- |
| `id` | Уникальное служебное имя латиницей: `update-skt-82-roof`. Только маленькие буквы, цифры и дефисы. |
| `title` | Название объекта или короткая привязка, например `Дом СКТ-82 · Медведево`. |
| `stage` | Что происходит на фотографии, например `Монтаж кровли`. |
| `image.src` | Путь к фотографии, например `assets/construction/skt-82-roof-medvedevo.webp`. |
| `image.alt` | Короткое описание содержимого фотографии. |
| `published` | `true` показывает публикацию, `false` скрывает её. |
| `example` | Служебная пометка демонстрационного материала. Посетитель её не видит. Для реального фото ставьте `false` или удалите строку. |
| `order` | Порядок показа. Меньшее число показывается раньше. |

Не меняйте `"schemaVersion": 1`.

## Как безопасно обновить существующую публикацию

1. Откройте `content/construction-updates.json` в редакторе кода, например Visual Studio Code.
2. Найдите публикацию по строке `"id": "..."`, `title` или `stage`.
3. Если меняется только подпись, исправьте `title` или `stage`.
4. Для новой фотографии сначала добавьте файл в `assets/construction/`.
5. Затем замените путь в `image.src` и описание в `image.alt`.
6. Не меняйте `id` у уже опубликованной записи.
7. Сохраните файл и выполните проверку ниже.

Новую фотографию безопаснее сохранить под новым именем, а не перезаписывать старую. Тогда старый вариант легко вернуть, и браузер не покажет сохранённое старое изображение.

## Как добавить новую фотографию

1. Проверьте фотографию: на ней не должно быть запрещённых личных данных или материалов без разрешения.
2. Подготовьте файл 1448 × 1086 пикселей и сохраните его в `assets/construction/`.
3. В `content/construction-updates.json` найдите список `"items": [`.
4. Скопируйте целиком один существующий блок от `{` до соответствующей `}`.
5. Вставьте копию внутрь списка `items`.
6. Между соседними блоками поставьте запятую. После последнего блока запятая не нужна.
7. Придумайте новый уникальный `id`. Он не должен повторять даже скрытую запись.
8. Замените `title`, `stage`, `image.src` и `image.alt`.
9. Для реальной фотографии поставьте `"example": false`.
10. Укажите свободное значение `order`.
11. Сначала можно поставить `"published": false`. После проверки замените на `true`.

Для нескольких фотографий одного объекта создавайте отдельную запись на каждый этап. У них может совпадать `title`, но `id` должны быть разными:

```text
update-skt-82-frame
update-skt-82-roof
update-skt-82-facade
```

## Как временно скрыть фотографию

Найдите нужный блок и замените:

```json
"published": true
```

на:

```json
"published": false
```

Фотография исчезнет с сайта, но запись останется в файле. Чтобы вернуть её, снова поставьте `true`.

Это безопаснее, чем удалять блок целиком.

## Как изменить порядок

Поле `order` задаёт порядок слайдов:

```json
"order": 1
```

Фотография с `order: 1` показывается первой, с `order: 2` — второй. Используйте разные целые числа. Чтобы поменять две фотографии местами, поменяйте их числа `order`.

Если хотите показать ход одной стройки по времени, поставьте ранним этапам меньшие числа, а поздним — большие.

## Полный правильный пример файла

Ниже — полный рабочий пример `content/construction-updates.json`. Это образец структуры, а не команда удалить настоящие публикации.

```json
{
  "schemaVersion": 1,
  "items": [
    {
      "id": "update-frame-skt-65",
      "title": "Дом СКТ-65 · Йошкар-Ола",
      "stage": "Сборка каркаса",
      "image": {
        "src": "assets/construction/frame-assembly-example.webp",
        "alt": "Сборка деревянного каркаса одноэтажного дома"
      },
      "published": true,
      "example": false,
      "order": 1
    },
    {
      "id": "update-roof-skt-65",
      "title": "Дом СКТ-65 · Йошкар-Ола",
      "stage": "Монтаж кровли",
      "image": {
        "src": "assets/construction/roof-installation-example.webp",
        "alt": "Монтаж металлической кровли на каркасном доме"
      },
      "published": true,
      "example": false,
      "order": 2
    },
    {
      "id": "update-facade-skt-65",
      "title": "Дом СКТ-65 · Йошкар-Ола",

        "src": "assets/construction/facade-installation-example.webp",
        "alt": "Монтаж деревянной фасадной отделки каркасного дома"

      "published": true,
      "example": false,
      "order": 3
    }
  ]
}
```

## Как проверить результат

1. Убедитесь, что файл называется `construction-updates.json`, а не `construction-updates.json.txt`.
2. Проверьте, что фотография существует по пути из `image.src`.
3. Проверьте JSON способом из раздела [«После изменения JSON пропал целый раздел сайта»](10-troubleshooting.md#после-изменения-json-пропал-целый-раздел-сайта). Ошибок быть не должно.
4. Откройте сайт через локальный веб-сервер и нажмите `Ctrl + F5`.
5. Перейдите к блоку «Со стройплощадки».
6. Стрелками откройте каждую фотографию.
7. Проверьте порядок, название объекта и этап.
8. Убедитесь, что стрелки и нижняя подпись не закрывают важные детали.
9. Подождите несколько секунд: слайды должны переключаться автоматически.
10. Проверьте блок в узком окне или на телефоне. Главная часть работ должна оставаться видимой.

Если вместо фотографий появилось сообщение «Не удалось загрузить раздел», проверьте JSON и повторяющиеся `id`.

## Частые ошибки

- **Ожидают, что блок «Проекты в работе» обновится сам.** Эти два блока меняются в разных файлах.
- **Повторили `id`.** Для каждого этапа нужен отдельный уникальный `id`.
- **Использовали русские буквы в `id`.** Нужны маленькие латинские буквы, цифры и дефисы.
- **Перепутали `title` и `stage`.** `title` — объект или место, `stage` — работа на фотографии.
- **Путь содержит обратный слэш.** Правильно: `assets/construction/file.webp`.
- **Имя или расширение не совпадает с реальным файлом.** Проверьте также большие и маленькие буквы.
- **Фотография слишком тяжёлая.** Она будет долго загружаться на телефоне. Сжимайте до 500 КБ.
- **Главный объект находится у края.** На другом экране сайт может его обрезать.
- **Важная деталь находится справа сверху или снизу.** Её закроют элементы управления и подпись.
- **На фотографии остались личные данные или люди без согласия.** Не публикуйте такой файл.
- **Забыли запятую между записями** или оставили её после последней записи.
- **Удалили фотографию вместо скрытия.** Используйте `"published": false`.
