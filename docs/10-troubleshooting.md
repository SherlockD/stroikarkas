# Решение частых проблем

Если что-то не получилось, не паникуйте. GitHub Desktop обычно сохраняет работу на компьютере, пока вы сами не попросите её удалить.

Главное правило: не нажимайте **Discard changes**, **Reset**, **Force push** и не создавайте **fork**. Если инструкции ниже не помогли, оставьте программы открытыми и обратитесь к разработчику.

## Сайт открыт, а проекты и отзывы пропали

Посмотрите на адрес страницы. Если он начинается с `file:///`, сайт открыт двойным щелчком и работает неправильно.

Закройте эту вкладку и запустите сайт через Live Server:

1. Откройте в VS Code весь проект `stroikarkas`.
2. Найдите `index.html`.
3. Нажмите на него правой кнопкой мыши.
4. Выберите **Open with Live Server**.

Правильный адрес начинается с `http://127.0.0.1:` или `http://localhost:`.

Причина: при открытии через `file:///` браузер может запретить загрузку файлов из папки `content`. Данные при этом не удаляются.

## В меню нет Open with Live Server

1. В VS Code нажмите значок **Extensions** слева.
2. Найдите `Live Server` от **Ritwick Dey**.
3. Если видна кнопка **Install**, нажмите её.
4. Если видна кнопка **Enable**, нажмите её.
5. Полностью закройте и снова откройте VS Code.
6. Снова нажмите правой кнопкой на `index.html`.

Если команда не появилась, не открывайте сайт двойным щелчком. Обратитесь к разработчику за настройкой Live Server.

## Проекта stroikarkas нет в GitHub Desktop

Если папка проекта уже есть на компьютере:

1. Выберите **File → Add local repository**.
2. Нажмите **Choose**.
3. Выберите папку `stroikarkas`, внутри которой находится `index.html`.
4. Нажмите **Add repository**.

Если папки нет, выберите **File → Clone repository**, откройте вкладку **URL** и используйте адрес `https://github.com/SherlockD/stroikarkas.git`.

Не выбирайте **Create new repository**, **Publish repository** или создание fork.

## При клонировании GitHub Desktop пишет, что папка уже существует

Скорее всего, проект уже скачан на компьютер. Не создавайте вторую копию в той же папке.

1. Нажмите **Cancel**.
2. Выберите **File → Add local repository**.
3. Укажите существующую папку `stroikarkas`.

Если GitHub Desktop не принимает её, не удаляйте и не переименовывайте папку. Выберите другое место для клонирования или обратитесь к разработчику.

## Add local repository сообщает, что это не репозиторий

Возможные причины:

- выбрана не сама папка `stroikarkas`, а папка выше или ниже;
- проект раньше скачали как ZIP-архив;
- служебная история проекта отсутствует.

Проверьте, что внутри выбранной папки видны `index.html`, `assets`, `content` и `docs`.

Если это ZIP-копия, не нажимайте **Create a repository** и **Publish repository**. Сохраните её как есть и клонируйте правильный проект через **File → Clone repository** в другую папку.

## Выбран другой проект или другая ветка

В верхней части GitHub Desktop должны быть:

- **Current repository** — `stroikarkas`;
- **Current branch** — `main`.

Если значения другие, не делайте коммит и не отправляйте изменения. Особенно важно не переключать ветки, если в **Changes** уже есть файлы. Обратитесь к разработчику.

## До начала работы в Changes уже есть файлы

Это может быть незаконченная работа с прошлого раза.

1. Не нажимайте **Discard changes**.
2. Не начинайте новые изменения в тех же файлах.
3. Нажмите на каждый файл и посмотрите его содержимое справа.
4. Если вы точно узнаёте свою прошлую работу, сначала закончите и проверьте её.
5. Если происхождение хотя бы одного файла непонятно, остановитесь и обратитесь к разработчику.

Случайные старые и новые изменения не нужно смешивать в одном коммите.

## Изменения не появились в Changes

Проверьте по порядку:

1. Сохранён ли файл в VS Code сочетанием `Ctrl+S`.
2. Открыт ли в GitHub Desktop проект `stroikarkas`.
3. Открывали ли вы VS Code через **Repository → Open in Visual Studio Code**.
4. Совпадает ли папка: в GitHub Desktop выберите **Repository → Show in Explorer**, а затем сравните её с папкой, открытой в VS Code.
5. Действительно ли новое значение отличается от старого.

Если всё совпадает, но список пуст, не создавайте новый репозиторий. Обратитесь к разработчику.

## Кнопка Commit to main не нажимается

Проверьте:

- в **Changes** отмечен галочкой хотя бы один файл;
- поле **Summary** заполнено;
- выбрана ветка `main`.

Если файлов нет, сначала сохраните изменения в VS Code. Если выбрана другая ветка, не переключайте её при наличии изменений — обратитесь к разработчику.

## Fetch origin или Pull origin не срабатывает

Сначала проверьте интернет: откройте [репозиторий проекта](https://github.com/SherlockD/stroikarkas) в браузере.

Затем:

1. Подождите минуту и повторите **Fetch origin**.
2. Если GitHub Desktop просит войти, используйте **File → Options → Accounts → Sign Into GitHub.com**.
3. Войдите через **Continue With Browser** в учётную запись с правом записи.

Если в **Changes** уже есть ваши файлы, а при Pull появляется предупреждение, ничего не подтверждайте. Работа на компьютере важнее — обратитесь к разработчику.

## GitHub Desktop предлагает создать fork

Нажмите **Cancel**.

Fork — отдельная копия проекта в вашей учётной записи. Для редактора сайта она не нужна. Такое предложение обычно означает, что у текущей учётной записи нет права записи в `SherlockD/stroikarkas`.

1. Проверьте учётную запись в **File → Options → Accounts**.
2. Убедитесь, что приглашение в репозиторий принято.
3. Попросите владельца подтвердить право **Write**.
4. После исправления доступа повторите **Push origin**.

Не соглашайтесь на создание fork даже «временно»: изменения уйдут не в тот проект и не обновят настоящий сайт.

## Ошибка доступа, authentication failed или permission denied

GitHub не разрешил доступ. Возможные причины:

- выполнен вход не в ту учётную запись;
- приглашение в проект не принято;
- нет права **Write**;
- вход в GitHub Desktop устарел.

Что сделать:

1. Откройте **File → Options → Accounts**.
2. Проверьте имя учётной записи.
3. При необходимости выйдите и снова нажмите **Sign Into GitHub.com**.
4. Выполните вход через браузер.
5. Попросите владельца проекта проверить ваше право **Write**.

Никому не отправляйте пароль, код подтверждения или секретный токен. Для помощи достаточно имени учётной записи и полного текста ошибки.

## GitHub Desktop сообщает о конфликте

Конфликт означает, что вы и другой человек изменили одно и то же место, а программа не знает, какой вариант оставить.

Не выбирайте вариант наугад.

1. Не нажимайте **Continue merge**.
2. Не нажимайте **Discard changes**.
3. Не используйте **Reset** или **Force push**.
4. Не закрывайте VS Code и GitHub Desktop.
5. Запишите полный текст сообщения и имена файлов с конфликтами.
6. Обратитесь к разработчику.

Так можно сохранить обе версии и аккуратно выбрать правильные данные.

## Появилась кнопка Force push

Не нажимайте её.

Обычная работа редактора заканчивается кнопкой **Push origin**. **Force push** означает принудительную замену истории на GitHub и может затереть чужую работу.

Оставьте программы открытыми и обратитесь к разработчику.

## Появилась кнопка Publish repository

Не нажимайте её. Настоящий репозиторий уже существует на GitHub.

Кнопка **Publish repository** обычно означает, что в GitHub Desktop подключена обычная папка или не тот проект.

1. Проверьте **Current repository**.
2. Выберите **File → Add local repository** и укажите правильную папку `stroikarkas`.
3. Если правильная папка не подключается, обратитесь к разработчику.

Публикация нового репозитория создаст лишний проект и не обновит настоящий сайт.

## Случайно нажали Discard changes

Больше ничего не нажимайте и не очищайте Корзину Windows. GitHub Desktop обычно помещает удалённые таким способом изменения в Корзину, но восстанавливать их лучше вместе с разработчиком.

Сообщите, какой файл был выбран и когда это произошло.

## После изменения JSON пропал целый раздел сайта

Скорее всего, в JSON допущена опечатка. Частые причины:

- пропущенная или лишняя запятая;
- пропущенная кавычка;
- скобка без пары;
- два одинаковых значения `id`;
- неверное имя поля или путь к изображению.

VS Code обычно подчёркивает синтаксическую ошибку красным.

1. Найдите красное подчёркивание.
2. Наведите на него указатель и прочитайте подсказку.
3. Сравните изменённую запись с соседней рабочей записью.
4. Исправьте ошибку и снова откройте сайт через Live Server.

Если причина неясна, не делайте **Commit to main** и **Push origin**. Оставьте изменения на компьютере и передайте разработчику имя JSON-файла.

## Изображение не появилось

Проверьте:

1. Сам файл находится внутри папки `assets`.
2. Имя файла в JSON и в папке совпадает буква в букву.
3. Путь в JSON записан через `/`.
4. Совпадает регистр букв: `House.webp` и `house.webp` на сайте могут считаться разными именами.
5. В GitHub Desktop в **Changes** видны и изображение, и изменённый JSON-файл.
6. Перед коммитом у обоих файлов стоят галочки.

После исправления снова проверьте страницу через Live Server.

## Push origin отклонён

Не ищите кнопку **Force push** и не создавайте fork.

Если GitHub Desktop сообщает, что на GitHub появились новые изменения:

1. Нажмите **Fetch origin**.
2. Нажмите **Pull origin**, если программа предлагает эту кнопку.
3. Если Pull закончился без предупреждений, снова нажмите **Push origin**.
4. Если появился конфликт или другое предупреждение, остановитесь и обратитесь к разработчику.

Если сообщается об отсутствии доступа, используйте раздел [Ошибка доступа, authentication failed или permission denied](#ошибка-доступа-authentication-failed-или-permission-denied).

## Изменения отправлены, но на сайте их нет

Проверьте по порядку:

1. В GitHub Desktop должна снова отображаться кнопка **Fetch origin**, а в **Changes** не должно быть неотправленных файлов текущей задачи.
2. Откройте [Actions проекта](https://github.com/SherlockD/stroikarkas/actions).
3. Найдите самую верхнюю задачу **pages build and deployment** для ветки `main`.
4. Дождитесь зелёной галочки. Обычно это занимает около минуты, иногда несколько минут.
5. Откройте [настоящий сайт](https://sherlockd.github.io/stroikarkas/).
6. Нажмите `Ctrl+F5`.

Если задача отмечена красным крестом, откройте её, скопируйте название и видимый текст ошибки и отправьте разработчику. Не меняйте **Settings → Pages** самостоятельно.

Если галочка зелёная, но данные старые, подождите две-три минуты, снова нажмите `Ctrl+F5` и проверьте сайт в приватном окне браузера.

## Случайно опубликовали неправильные данные

Не удаляйте старый коммит и не используйте Reset.

Самый безопасный способ — создать обычное исправление:

1. Исправьте данные в VS Code.
2. Сохраните файл.
3. Проверьте сайт через Live Server.
4. В GitHub Desktop просмотрите **Changes**.
5. Оставьте галочки только у исправленных файлов.
6. В **Summary** напишите, что исправлено.
7. Нажмите **Commit to main**.
8. Нажмите **Push origin**.

Новый коммит исправит настоящий сайт и сохранит понятную историю.

## Что сообщить разработчику

Чтобы помощь была быстрой, передайте:

1. Что вы хотели изменить.
2. На каком шаге появилась проблема.
3. Полный текст сообщения на экране.
4. Что указано в **Current repository** и **Current branch**.
5. Имена файлов в разделе **Changes**.
6. Какие кнопки вы нажали перед появлением проблемы.

Не отправляйте пароли, коды подтверждения и другие секретные данные.
