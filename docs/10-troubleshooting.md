# Решение частых проблем

[← Вернуться к списку инструкций](README.md)

Если что-то не получилось, не паникуйте: Git обычно не теряет файлы сам. Прочитайте сообщение об ошибке целиком и найдите похожий случай ниже.

Главное правило: не используйте `git push --force`, `git reset --hard` и команды удаления. Если инструкция ниже не помогла, остановитесь и отправьте разработчику текст ошибки.

## Сайт открыли двойным щелчком, а проекты и отзывы пропали

Посмотрите на адрес страницы. Если он начинается с `file:///`, сайт открыт неправильно.

Закройте эту вкладку и запустите сайт через Live Server:

1. Откройте в VS Code всю папку `stroikarkas`.
2. Нажмите правой кнопкой на `index.html`.
3. Выберите **Open with Live Server**.

Правильный адрес начинается с `http://127.0.0.1:` или `http://localhost:`.

Причина: при открытии через `file:///` браузер может запретить загрузку JSON-файлов из папки `content`.

## В меню нет Open with Live Server

1. Нажмите в VS Code значок **Extensions** («Расширения») слева.
2. Найдите `Live Server` от **Ritwick Dey**.
3. Если рядом есть кнопка **Install**, нажмите её.
4. Если есть кнопка **Enable**, нажмите её.
5. Закройте и снова откройте VS Code.

Если расширение всё равно не работает, откройте терминал VS Code. Сначала проверьте папку:

```powershell
Get-Location
```

Путь должен заканчиваться на `stroikarkas`. Только после этого запустите запасной сервер:

```powershell
py -m http.server --bind 127.0.0.1 8000
```

Затем откройте [http://localhost:8000/](http://localhost:8000/). Остановить сервер можно сочетанием `Ctrl+C` в терминале.

## PowerShell пишет, что порт 8000 уже используется

Это значит, что на порту уже работает другая программа. Запустите сервер на другом порту:

```powershell
py -m http.server --bind 127.0.0.1 8001
```

Откройте [http://localhost:8001/](http://localhost:8001/).

## Git не запускается

Сообщение может выглядеть так: `git is not recognized` или «Имя git не распознано».

1. Закройте все окна PowerShell и VS Code.
2. Откройте их снова.
3. Выполните:

```powershell
git --version
```

Если ошибка осталась, установите Git с [официальной страницы](https://git-scm.com/install/windows). Во время установки оставьте предложенные настройки. После установки снова перезапустите VS Code.

## Команда code не запускается

Сообщение может выглядеть так: `code is not recognized`.

Git от этого не сломан. Откройте VS Code через меню «Пуск», затем выберите **File → Open Folder** («Файл → Открыть папку») и откройте `Документы\Sites\stroikarkas`.

После переустановки или обновления VS Code также помогает полностью закрыть и снова открыть PowerShell.

## Git пишет not a git repository

Вы выполняете команду не в папке проекта.

Посмотрите текущую папку:

```powershell
Get-Location
```

Если проект был установлен по основной инструкции, перейдите в него:

```powershell
Set-Location -LiteralPath (Join-Path ([Environment]::GetFolderPath('MyDocuments')) 'Sites\stroikarkas')
```

Проверьте:

```powershell
git status
```

Если папка проекта находится в другом месте, откройте её через VS Code и создайте новый терминал командой **Terminal → New Terminal**.

## Git pull не выполнился

Сначала выполните:

```powershell
git status --short
```

Если в списке есть изменённые файлы, значит работа на компьютере ещё не сохранена в коммите. Не удаляйте её и не запускайте случайные команды.

- Если это ваши нужные изменения, сначала проверьте их и сохраните обычным коммитом по инструкции [Git и публикация сайта](09-git-and-publishing.md), но пока не выполняйте `git push`. После коммита обратитесь к разработчику: он поможет получить чужие изменения и сохранить ваши.
- Если вы не знаете, откуда появились изменения, ничего не добавляйте в коммит и обратитесь к разработчику.

Если команда `git pull --ff-only origin main` сообщает `Not possible to fast-forward` или `divergent branches`, версии разошлись. Не убирайте `--ff-only` и не пытайтесь объединять их самостоятельно. Отправьте разработчику полный текст ошибки и результат `git status`.

## Git push сообщает rejected

Частая причина: другой человек отправил изменения раньше вас.

Не добавляйте `--force`.

Выполните только диагностические команды:

```powershell
git status
git branch --show-current
```

Скопируйте их ответы вместе с текстом ошибки и отправьте разработчику. Он поможет безопасно совместить две версии, не потеряв вашу работу.

## Ошибка 403, Permission denied или Authentication failed

GitHub не разрешил запись. Возможные причины:

- в браузере открыта не та учётная запись GitHub;
- приглашение в репозиторий ещё не принято;
- учётной записи не выдали право записи;
- сохранён устаревший вход.

Что сделать:

1. Откройте [репозиторий проекта](https://github.com/SherlockD/stroikarkas) в браузере.
2. Проверьте аватар в правом верхнем углу и имя учётной записи.
3. Проверьте уведомления и электронную почту: возможно, там ждёт приглашение в репозиторий.
4. Попросите владельца подтвердить, что у вашей учётной записи есть право **Write**.
5. После исправления доступа повторите обычную команду:

```powershell
git push origin main
```

Не отправляйте разработчику пароль, код подтверждения, токен или содержимое менеджера паролей. Для помощи достаточно текста ошибки и имени учётной записи.

## Git пишет nothing to commit

Это означает, что Git не видит новых изменений.

Проверьте:

1. Сохранили ли вы файл сочетанием `Ctrl+S`.
2. Тот ли проект открыт в VS Code.
3. Действительно ли новое значение отличается от старого.

Затем выполните:

```powershell
git status --short
```

Если команда ничего не показала, в проекте сейчас нет несохранённых в Git изменений.

## В git status появился незнакомый файл

Не используйте `git add .` и не добавляйте незнакомый файл в коммит.

Если файл уже был выбран для коммита, уберите его из списка:

```powershell
git restore --staged -- 'точный/путь/к/файлу'
```

Эта команда не удаляет файл и не стирает его содержимое. После неё снова выполните `git status --short` и обратитесь к разработчику.

## В файле видны строки с <<<<<<<, ======= и >>>>>>>

Это конфликт: Git нашёл две разные версии одних и тех же строк и не смог выбрать правильную.

Не удаляйте метки наугад, не создавайте коммит и не выполняйте `push --force`. Оставьте VS Code открытым и обратитесь к разработчику. Так обе версии можно будет сохранить и аккуратно объединить.

## После изменения JSON пропал целый раздел сайта

Скорее всего, в JSON допущена опечатка. Чаще всего это:

- пропущенная или лишняя запятая;
- пропущенная кавычка `"`;
- фигурная или квадратная скобка без пары;
- два одинаковых значения `id`;
- неверный путь к изображению.

VS Code обычно подчёркивает синтаксическую ошибку красным. Наведите курсор на подчёркнутое место и прочитайте подсказку.

Можно безопасно проверить синтаксис через PowerShell. Для каталога проектов команда выглядит так:

```powershell
Get-Content -Raw -LiteralPath 'content\projects.json' | ConvertFrom-Json | Out-Null
```

Для другого раздела замените `projects.json` на нужное имя файла. Если команда ничего не вывела, скобки, запятые и кавычки записаны правильно. Если появилась красная ошибка, исправьте указанное место и повторите проверку.

Даже при правильном синтаксисе раздел может не загрузиться из-за повторяющегося `id` или неправильного поля. Сравните запись с соседней рабочей записью. Если причина неясна, не публикуйте изменение и отправьте разработчику изменённый JSON-файл.

## Изображение не появилось

Проверьте по порядку:

1. Файл изображения действительно находится внутри папки `assets`.
2. Имя файла в JSON и на диске совпадает буква в букву.
3. В JSON путь записан через `/`, например `assets/projects/house/new-house.webp`.
4. В имени и расширении совпадает регистр букв: для GitHub `House.webp` и `house.webp` могут быть разными именами.
5. Новый файл виден в результате команды:

```powershell
git status --short
```

6. При создании коммита были добавлены и JSON, и само изображение:

```powershell
git add -- 'content/projects.json' 'assets/projects/house/new-house.webp'
```

Замените пути на настоящие. После исправления снова проверьте сайт через Live Server.

## Изменения отправлены, но на сайте их нет

Проверьте по порядку:

1. Выполните:

```powershell
git status
```

2. Убедитесь, что есть строка `Your branch is up to date with 'origin/main'.`.
3. Откройте [Actions проекта](https://github.com/SherlockD/stroikarkas/actions).
4. Найдите самую верхнюю задачу **pages build and deployment** для `main`.
5. Дождитесь зелёной галочки. Обычно это занимает около минуты, иногда несколько минут.
6. Откройте [настоящий сайт](https://sherlockd.github.io/stroikarkas/).
7. Нажмите `Ctrl+F5`.

Если у задачи красный крест, откройте её и отправьте разработчику снимок экрана. Не меняйте настройки **Settings → Pages** самостоятельно.

Если галочка зелёная, но старые данные остаются, подождите две-три минуты, снова нажмите `Ctrl+F5` и проверьте страницу в приватном окне браузера.

## Случайно опубликовали неправильные данные

Самый безопасный способ — сделать новое исправление:

1. Исправьте данные в файле.
2. Сохраните файл сочетанием `Ctrl+S`.
3. Проверьте сайт через Live Server.
4. Добавьте только исправленный файл.
5. Создайте новый коммит, например:

```powershell
git add -- 'content/projects.json'
git commit -m "Исправлена ошибка в каталоге проектов"
git push origin main
```

Не переписывайте старый коммит и не удаляйте историю. Новый коммит безопасно исправит сайт.

## Что отправить разработчику

Чтобы помощь была быстрой, пришлите:

1. Что вы хотели изменить.
2. На каком шаге появилась проблема.
3. Полный текст ошибки или снимок экрана.
4. Результаты команд:

```powershell
git status
git branch --show-current
```

5. Имена файлов, которые вы меняли.

Не присылайте пароли, коды из SMS, токены и другие секретные данные.
