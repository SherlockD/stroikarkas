# Как менять блок «Проекты в работе»

[← Вернуться к списку инструкций](README.md)

## Что изменяет эта инструкция

Блок «Проекты в работе» находится на первом экране сайта. В нём по очереди показываются объекты, которые сейчас строятся: фотография, код проекта, короткий статус, этап работ и площадь.

Этот блок не связан с каталогом автоматически. Если вы изменили проект в `projects.json`, запись «Проекты в работе» сама не изменится. Её нужно исправить отдельно по этой инструкции.

## Где находятся текст и фотографии

- Все данные блока: `content/current-builds.json`.
- Фотографии текущей стройки удобно хранить в существующей папке `assets/construction/`.

Для каждого нового объекта давайте фотографии отдельное понятное имя, например:

```text
assets/construction/build-skt-82-roof.webp
```

Имя файла пишите маленькими латинскими буквами, без пробелов. Слова разделяйте дефисами.

В JSON путь пишется с прямыми слэшами `/`. Не используйте путь с диском (`C:\...`), обратные слэши (`\`) или первый слэш перед `assets`.

## Как подготовить фотографию

В этом блоке фотография показывается в квадратной рамке.

- рекомендуемый размер — **1200 × 1200 пикселей**;
- пропорции — **1:1**, то есть квадрат;
- лучший формат — **WebP**;
- можно использовать JPEG (`.jpg`);
- рекомендуемый вес — **до 500 КБ**.

Если исходная фотография горизонтальная, заранее обрежьте её до квадрата. Дом или баня должны находиться ближе к центру. Сайт заполняет фотографией всю рамку, поэтому края горизонтального или вертикального снимка будут обрезаны.

Не добавляйте рамки и важные надписи по краям. На телефоне их может быть не видно.

Поле `alt` кратко описывает фотографию. Хороший вариант: `Монтаж кровли каркасного дома СКТ-82`. Плохой вариант: `Фото 1`.

## Что означают поля

| Поле | Что писать |
| --- | --- |
| `id` | Уникальное служебное имя латиницей, например `build-skt-82`. Только маленькие буквы, цифры и дефисы. |
| `projectCode` | Код проекта или понятное имя объекта, которое увидит посетитель: `СКТ-82`. |
| `status` | Короткий статус, например `Строим в Медведево` или `Дом для постоянного проживания`. |
| `stage` | Текущий этап без слова «Этап:», например `Монтаж кровли`. Сайт сам добавит слово «Этап». |
| `area` | Площадь числом без кавычек и без `м²`: `82.5`. Для дробной части используйте точку. |
| `image.src` | Путь к фотографии от корня проекта, например `assets/construction/build-skt-82-roof.webp`. |
| `image.alt` | Короткое описание того, что видно на фотографии. |
| `published` | `true` показывает объект, `false` скрывает его. |
| `example` | Служебная пометка демонстрационного материала. Посетитель её не видит. Для настоящего объекта ставьте `false` или удалите строку. |
| `order` | Порядок показа. Меньшее число показывается раньше. |

Не меняйте `"schemaVersion": 1`.

## Как безопасно изменить существующий объект

1. Откройте `content/current-builds.json` в редакторе кода, например Visual Studio Code.
2. Найдите объект по строке `"id": "..."` или `"projectCode": "..."`.
3. Для обычного обновления этапа поменяйте только значение `stage`.
4. Если нужно, замените `status`, `area` и фотографию.
5. Новую фотографию сначала положите в `assets/construction/`, затем исправьте `image.src`.
6. Не меняйте `id` у уже опубликованной записи.
7. Сохраните файл и выполните проверку ниже.

Фотографию безопаснее добавлять под новым именем, а не перезаписывать старый файл. Тогда при ошибке можно быстро вернуть прежний путь.

## Как добавить новый объект

1. Подготовьте квадратную фотографию и положите её в `assets/construction/`.
2. В `content/current-builds.json` найдите список `"items": [`.
3. Скопируйте целиком один существующий блок от `{` до соответствующей `}`.
4. Вставьте копию внутрь списка `items`.
5. Между соседними блоками должна стоять запятая. После последнего блока запятая не нужна.
6. Задайте новый уникальный `id`, например `build-skt-82-medvedevo`.
7. Замените код, статус, этап, площадь, путь и описание фотографии.
8. Для настоящего объекта поставьте `"example": false`.
9. Укажите свободное значение `order`.
10. Сначала можно оставить `"published": false`. После проверки замените `false` на `true`.

Один и тот же проект можно строить в нескольких местах. В таком случае у записей могут совпадать `projectCode`, но `id` обязательно должны быть разными, например `build-skt-82-medvedevo` и `build-skt-82-yoshkar-ola`.

## Как временно скрыть объект

Найдите нужный блок и замените:

```json
"published": true
```

на:

```json
"published": false
```

Запись останется в файле, но исчезнет с сайта. Когда объект снова понадобится, верните `true`.

Если стройка завершена, обычно её нужно скрыть здесь и отдельно добавить в «Реализованные проекты» по инструкции [05-completed-projects.md](05-completed-projects.md).

## Как изменить порядок

Поле `order` определяет, какой объект посетитель увидит первым:

```json
"order": 1
```

Используйте разные целые числа: `1`, `2`, `3` и так далее. Чем меньше число, тем раньше слайд. Чтобы поменять два объекта местами, поменяйте их числа `order`.

## Полный правильный пример файла

Ниже — полный рабочий пример `content/current-builds.json`. Это образец структуры, а не команда удалить настоящие записи.

```json
{
  "schemaVersion": 1,
  "items": [
    {
      "id": "build-skt-65",
      "projectCode": "СКТ-65",
      "status": "Строим в Йошкар-Оле",
      "stage": "Монтаж внешней отделки",
      "area": 65.68,
      "image": {
        "src": "assets/projects/house/skt-65-cover.webp",
        "alt": "Каркасный дом СКТ-65 на этапе внешней отделки"
      },
      "published": true,
      "example": false,
      "order": 1
    },
    {
      "id": "build-skb-36",
      "projectCode": "СКБ-36",
      "status": "Строим в Медведево",
      "stage": "Устройство кровли",
      "area": 36,
      "image": {
        "src": "assets/projects/bath/skb-36-cover.webp",
        "alt": "Каркасная баня СКБ-36 на этапе устройства кровли"
      },
      "published": true,
      "example": false,
      "order": 2
    }
  ]
}
```

## Как проверить результат

1. Убедитесь, что файл называется `current-builds.json`, а не `current-builds.json.txt`.
2. Проверьте, что новая фотография добавлена в проект и её имя полностью совпадает со строкой `image.src`.
3. Проверьте JSON способом из раздела [«После изменения JSON пропал целый раздел сайта»](10-troubleshooting.md#после-изменения-json-пропал-целый-раздел-сайта). Ошибок быть не должно.
4. Откройте сайт через локальный веб-сервер.
5. Обновите страницу сочетанием `Ctrl + F5`.
6. На первом экране найдите блок «Проекты в работе».
7. Проверьте фотографию, код, статус, этап и площадь каждого объекта стрелками карусели.
8. Подождите несколько секунд и убедитесь, что карточки переключаются автоматически.
9. Проверьте блок в узком окне или на телефоне. Главный объект не должен быть обрезан.

Если вместо карточек появилось сообщение «Не удалось загрузить раздел», проверьте JSON и повторяющиеся `id`.

## Частые ошибки

- **Изменили каталог и ждут, что этот блок обновится сам.** `current-builds.json` нужно менять отдельно.
- **Повторили `id`.** `projectCode` повторяться может, `id` — нет.
- **Написали `id` русскими буквами.** Используйте только маленькие латинские буквы, цифры и дефисы.
- **Написали `"stage": "Этап: Монтаж кровли"`.** Сайт сам добавляет «Этап:», поэтому получится повтор.
- **Написали площадь как `65,68 м²`.** Нужно `65.68` без кавычек и единиц измерения.
- **Фотография слишком широкая.** Сайт обрежет края. Используйте квадрат и держите объект в центре.
- **Путь начинается с `/` или содержит `\`.** Правильно: `assets/construction/file.webp`.
- **Регистр букв не совпадает.** `Build-1.webp` и `build-1.webp` на опубликованном сайте могут считаться разными файлами.
- **Забыли запятую между блоками** или оставили запятую после последнего блока.
- **Использовали кавычки `“ ”`.** В JSON нужны обычные двойные кавычки `"`.
- **Удалили завершённый объект.** Безопаснее скрыть его через `"published": false`.
