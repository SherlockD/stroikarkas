# Требования к изображениям

[← Вернуться к списку инструкций](README.md)

Правильно подготовленная фотография быстро загружается, не выглядит размытой и не обрезает важную часть объекта. Перед добавлением изображения проверьте размер в пикселях, формат, вес файла и имя.

## Короткая таблица

| Где используется | Размер в пикселях | Пропорции | Формат | Максимальный вес |
| --- | ---: | ---: | --- | ---: |
| Проект в каталоге | 1448 × 1086 | 4:3 | WebP | ≤ 500 КБ |
| Готовый объект с фотографией | 1448 × 1086 | 4:3 | WebP | ≤ 500 КБ |
| Фотография со стройки | 1448 × 1086 | 4:3 | WebP | ≤ 500 КБ |
| Проект в работе на первом экране | 1200 × 1200 | 1:1, квадрат | WebP | ≤ 500 КБ |
| Фотография к отзыву | 1500 × 1000 | 3:2 | WebP | ≤ 500 КБ |
| Обложка видео | 1280 × 720 | 16:9 | WebP или JPEG | ≤ 300 КБ |
| Фотография компании или сотрудника | 1600 × 1200 | 4:3 | WebP | ≤ 500 КБ |
| Логотип `stroikarkas-logo-mark.png` | 640 × 640 | 1:1, квадрат | PNG | ≤ 200 КБ |
| Иконка сайта `favicon.png` | 512 × 512 | 1:1, квадрат | PNG | ≤ 300 КБ |

`КБ` — килобайты, то есть вес файла. Чем он меньше, тем быстрее загрузится сайт. Для фотографии не нужно пытаться получить ровно 500 КБ: 250–400 КБ лучше, если качество остаётся хорошим.

Логотип и иконка сайта уже подготовлены. Не заменяйте их обычными фотографиями и не меняйте их пропорции. Если нужен новый логотип, передайте исходник разработчику или дизайнеру.

## Особенность первого экрана

На первом экране фотография показывается в квадратной области. Лучший вариант — сразу подготовить квадрат `1200 × 1200`.

Если доступна только горизонтальная фотография `1448 × 1086`, её можно использовать, но дом, баня или беседка должны находиться ближе к центру. Края фотографии будут обрезаны. Не размещайте у краёв:

- важную часть здания;
- лицо человека;
- надпись;
- логотип;
- единственный значимый предмет.

Это правило полезно и для остальных фотографий: сайт использует автоматическую обрезку под карточки разных размеров.

## Как назвать файл

Используйте:

- только латинские буквы `a-z`;
- цифры;
- дефисы между словами;
- правильное окончание формата: `.webp`, `.jpg` или `.png`.

Хорошие имена:

```text
skt-65-front.webp
bath-medvedevo-2026.webp
review-ivan-petrov.webp
roof-installation-02.webp
```

Плохие имена:

```text
Фото дома 1.webp
новая_баня.webp
IMG 0042.JPG
финал-финал2.webp
```

Не используйте пробелы, кириллицу и случайные длинные имена с телефона. На опубликованном сайте регистр букв важен: `House.webp` и `house.webp` считаются разными файлами.

Не меняйте только окончание имени вручную. Переименование `photo.jpg` в `photo.webp` не превращает JPEG в WebP. Файл нужно экспортировать или сохранить в новом формате через редактор изображения.

## Куда положить файл

Используйте подходящую папку внутри `assets`:

- дома: `assets/projects/house/`;
- бани: `assets/projects/bath/`;
- беседки: `assets/projects/gazebo/`;
- фотографии со стройки: `assets/construction/`;
- фотографии отзывов: можно создать `assets/reviews/`;
- сотрудники: можно создать `assets/team/`;
- компания: можно создать `assets/company/`.

Обложку видео можно хранить в `assets/` или в отдельной понятной подпапке. Главное — точно указать тот же путь в JSON или `index.html`.

### Как скопировать подготовленный файл

1. В левой части VS Code найдите папку `assets` и раскройте её стрелкой.
2. Нажмите нужную папку правой кнопкой мыши и выберите **Reveal in File Explorer** или **Открыть в проводнике**.
3. Скопируйте подготовленную фотографию в открывшуюся папку обычным способом.
4. Вернитесь в VS Code. Новый файл должен появиться слева внутри этой папки.
5. Если нужна новая папка, например `reviews`, нажмите правой кнопкой по `assets`, выберите **New Folder** и напишите имя маленькими латинскими буквами.

Не оставляйте фотографию только в папке «Загрузки» или на рабочем столе: сайт получает файлы лишь из своей папки `assets`.

В JSON и HTML путь пишется через прямой слэш `/`:

```text
assets/projects/house/skt-65-front.webp
```

Не пишите обратный слэш `\`, даже если Windows показывает пути именно так.

Для обновлённой фотографии безопаснее использовать новое имя, например `skt-65-front-2026.webp`, и изменить путь в записи. Тогда браузер не покажет старую фотографию из памяти. После проверки ненужный старый файл можно удалить отдельным изменением.

Не заменяйте файл `assets/image-placeholder.png` фотографией одного объекта. Это общий временный заполнитель для разных мест сайта.

## Как подготовить фотографию без онлайн-сервиса

Используйте установленный на компьютере редактор фотографий. Названия кнопок могут немного отличаться, но порядок один и тот же.

1. Скопируйте исходную фотографию и работайте с копией.
2. Откройте копию в редакторе.
3. Выберите инструмент «Обрезка» или «Кадрирование».
4. Укажите нужные пропорции из таблицы: `4:3`, `3:2`, `16:9` или `1:1`.
5. Сдвиньте рамку так, чтобы главный объект оказался ближе к центру.
6. Выберите «Изменить размер» и укажите размеры в пикселях из таблицы.
7. Выберите «Экспорт» или «Сохранить как».
8. Для фотографии выберите WebP. Если редактор предлагает качество, начните с 80–85%.
9. Сохраните файл под новым понятным именем.
10. В Проводнике Windows нажмите по файлу правой кнопкой мыши, откройте «Свойства» и проверьте размер файла. Размеры в пикселях обычно находятся на вкладке «Подробно».

Если файл тяжелее указанного в таблице, снова экспортируйте его с немного меньшим качеством. Не уменьшайте качество сразу до очень низкого: на стенах, крыше и деревьях появятся заметные квадраты и пятна.

Если установленный редактор не умеет сохранять WebP, не загружайте рабочие фотографии клиентов на случайный сайт-конвертер. Сохраните обработанную копию в качественном JPEG и передайте её разработчику для окончательной конвертации. Для регулярной работы разработчик может один раз установить проверенный офлайн-редактор с поддержкой WebP.

PNG используйте для логотипов, иконок и изображений с прозрачным фоном. Обычная фотография в PNG почти всегда весит слишком много. JPEG допустим для обложки видео; для остальных фотографий предпочтителен WebP.

Не добавляйте на сайт файлы прямо из камеры в форматах RAW или HEIC. Сначала экспортируйте их в формат из таблицы.

## Как написать `alt`

`alt` — это короткое текстовое описание фотографии. Его слышит человек, который использует программу чтения с экрана. Оно также помогает понять содержимое, если фотография не загрузилась.

Хороший `alt` отвечает на вопрос «Что показано на фотографии?»:

```json
"alt": "Одноэтажный каркасный дом СКТ–65 с крытой террасой"
```

Неудачные варианты:

```json
"alt": "Фото"
"alt": "Картинка дома"
"alt": "IMG 0042"
```

Не начинайте описание словами «фотография» или «изображение». Не вставляйте рекламу и длинный список ключевых слов. Обычно достаточно 5–15 слов.

Для фотографии сотрудника укажите имя и роль, например:

```html
alt="Алексей, архитектор компании СтройКаркас"
```

Пустой `alt=""` допустим только для декоративного изображения, которое ничего не добавляет к соседнему тексту. У логотипа в шапке пустой `alt` оставлен специально, потому что рядом уже написано название компании.

## Проверка перед публикацией

- Размеры и пропорции совпадают с таблицей.
- Вес файла не превышает ограничение.
- Формат соответствует настоящему формату файла, а не только окончанию имени.
- Имя написано латиницей, в нижнем регистре и без пробелов.
- Главный объект находится ближе к центру.
- Важные детали не прижаты к краям.
- `alt` понятно описывает содержимое.
- Путь в JSON или `index.html` точно совпадает с папкой и именем файла.
- Фотография открывается на сайте на компьютере и телефоне.
- На фотографии нет личных документов, номеров телефонов, автомобильных номеров или другой информации, которую нельзя публиковать.

После проверки сохраните и опубликуйте изменение по главе [09. GitHub Desktop и публикация сайта](09-git-and-publishing.md).
