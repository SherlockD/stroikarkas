# Как менять проекты в каталоге

[← Вернуться к списку инструкций](README.md)

## Что изменяет эта инструкция

Здесь описан раздел сайта **«Проекты»**. Это карточки домов, бань и беседок с кодом проекта, площадью, ценой, фотографиями и подробным описанием.

Изменения в этом файле **не меняют** блок «Проекты в работе». Он настраивается отдельно по инструкции [03-current-builds.md](03-current-builds.md).

## Где находятся текст и фотографии

- Все данные каталога: `content/projects.json`.
- Фотографии домов: `assets/projects/house/`.
- Фотографии бань: `assets/projects/bath/`.
- Фотографии беседок: `assets/projects/gazebo/`.

Название файла фотографии пишите латинскими буквами, маленькими буквами, без пробелов. Слова разделяйте дефисом. Например: `skd-72-cover.webp`.

В пути внутри JSON используйте только прямой слэш `/`:

```text
assets/projects/house/skd-72-cover.webp
```

Не пишите путь с диском (`C:\...`), обратными слэшами (`assets\...`) или первым слэшем (`/assets/...`). На опубликованном сайте важен регистр букв: `House` и `house` считаются разными названиями.

## Как подготовить изображения

Для обычной фотографии проекта:

- рекомендуемый размер — **1448 × 1086 пикселей**;
- пропорции — **4:3**, то есть горизонтальный прямоугольник;
- лучший формат — **WebP**;
- можно использовать JPEG (`.jpg`), если WebP сделать не получается;
- рекомендуемый вес одного файла — **до 500 КБ**.

Главный объект располагайте ближе к центру. На маленьком экране края фотографии могут немного обрезаться.

Для плана или схемы можно использовать WebP или PNG. Лучше также подготовить файл размером 1448 × 1086 пикселей. Если фон и мелкие надписи плохо видны в WebP, используйте PNG весом до 1 МБ.

Первая картинка в списке `images` показывается на карточке. Поэтому первой всегда ставьте красивую фотографию объекта. Планировку ставьте второй или третьей и добавляйте ей строку `"fit": "contain"` — тогда в большом окне схема поместится целиком.

Пример списка из фотографии и планировки:

```json
"images": [
  {
    "src": "assets/projects/house/skd-72-cover.webp",
    "alt": "Одноэтажный каркасный дом СКД-72 с террасой"
  },
  {
    "src": "assets/projects/house/skd-72-plan.png",
    "alt": "Планировка одноэтажного дома СКД-72",
    "fit": "contain"
  }
]
```

Поле `alt` — короткое описание того, что видно на картинке. Оно нужно людям, у которых изображение не загрузилось, и программам чтения с экрана. Не пишите «фото» или «картинка» — сразу опишите объект.

## Что означают поля проекта

| Поле | Что писать |
| --- | --- |
| `id` | Уникальное служебное имя. Только маленькие латинские буквы, цифры и дефисы: `skd-72`. После публикации лучше его не менять. |
| `category` | Только `house` для дома, `bath` для бани или `gazebo` для беседки. |
| `code` | Код, который увидит посетитель, например `СКД-72`. |
| `area` | Площадь числом, без кавычек и без `м²`: `72.5`. Для дробной части нужна точка, не запятая. |
| `price` | Цена числом, без кавычек, пробелов, слова «рублей» и знака рубля: `1750000`. |
| `package` | Короткая подпись рядом с кодом проекта, например `Базовая комплектация`. |
| `description` | Подробное описание проекта. |
| `features` | Несколько коротких преимуществ. Каждая строка находится в кавычках. |
| `parameters` | Данные, которые подставляются в форму расчёта, когда посетитель выбирает этот проект. |
| `images` | Список фотографий и планировок. Первая картинка является главной. |
| `published` | `true` показывает проект, `false` скрывает его. Кавычки не нужны. |
| `example` | Служебная пометка демонстрационного материала. Посетитель её не видит. Для настоящего проекта ставьте `false` или удалите эту строку. |
| `order` | Порядок внутри своей категории. Меньшее число показывается раньше. |

Не меняйте `"schemaVersion": 1`.

### Параметры для разных категорий

У дома должны быть:

```json
"parameters": {
  "floors": "Один этаж",
  "rooms": 3
}
```

Для `floors` используйте один из вариантов: `Один этаж`, `Один этаж с мансардой` или `Два этажа`. Для `rooms` укажите число от 1 до 20 без кавычек.

У бани должны быть:

```json
"parameters": {
  "length": "6",
  "width": "5",
  "bathRooms": "Парная, предбанник и моечная"
}
```

Для `bathRooms` используйте один из вариантов:

- `Парная и предбанник`;
- `Парная, предбанник и моечная`;
- `Парная, моечная и комната отдыха`;
- `Не знаю - нужна рекомендация`.

У беседки должны быть:

```json
"parameters": {
  "length": "4",
  "width": "4",
  "gazeboType": "Открытая"
}
```

Для `gazeboType` используйте один из вариантов:

- `Открытая`;
- `Закрытая или остеклённая`;
- `Пристроенная к дому`;
- `Не знаю - нужна рекомендация`.

Если написать другой вариант, карточка будет видна, но форма расчёта может заполниться не полностью.

## Как безопасно изменить существующий проект

1. Откройте `content/projects.json` в обычном редакторе кода, например Visual Studio Code. Не используйте Word.
2. Найдите проект по строке `"id": "..."` или `"code": "..."`.
3. Меняйте только нужные значения справа от двоеточия.
4. Если меняете фотографию, сначала положите новый файл в нужную папку, а затем замените путь в `src`.
5. Не меняйте `id`, если проект уже был опубликован.
6. Сохраните файл.
7. Выполните проверку из раздела «Как проверить результат» ниже.

Самый безопасный способ заменить фотографию — дать новому файлу новое имя. Например, не перезаписывать `skd-72-cover.webp`, а добавить `skd-72-cover-2026.webp` и поменять `src`. Так старую фотографию легко вернуть.

## Как добавить новый проект

1. Подготовьте фотографию и положите её в папку нужной категории.
2. В `content/projects.json` найдите большой список `"items": [`.
3. Скопируйте целиком один похожий проект: дом для дома, баню для бани, беседку для беседки.
4. Вставьте копию между соседними проектами внутри `items`.
5. Между двумя блоками проектов обязательно должна стоять запятая. После последнего блока запятая не нужна.
6. Придумайте новый `id`. Он не должен повторяться ни у одного проекта, даже у скрытого.
7. Замените все тексты, числа, параметры и пути к изображениям.
8. Для настоящего проекта поставьте `"example": false`.
9. Сначала можно поставить `"published": false`, проверить файл и только потом заменить на `true`.

Не добавляйте новую категорию в список `categories`. Сайт и форма расчёта сейчас рассчитаны только на `house`, `bath` и `gazebo`. Для новой категории нужна доработка сайта программистом.

## Как временно скрыть проект

Найдите нужный проект и замените:

```json
"published": true
```

на:

```json
"published": false
```

Проект останется в файле, но исчезнет с сайта. Это безопаснее удаления. Чтобы вернуть его, снова поставьте `true`.

## Как изменить порядок

Порядок задаёт поле `order` внутри каждой категории:

```json
"order": 1
```

Проект с числом `1` будет первым, с числом `2` — вторым и так далее. Используйте разные целые числа. Чтобы поменять два проекта местами, поменяйте их значения `order`.

Порядок домов не влияет на порядок бань и беседок.

## Как проверить результат

1. Убедитесь, что файл сохранился именно как `projects.json`, а не `projects.json.txt`.
2. Проверьте, что каждая новая фотография действительно находится по пути, написанному в `src`.
3. Проверьте JSON способом из раздела [«После изменения JSON пропал целый раздел сайта»](10-troubleshooting.md#после-изменения-json-пропал-целый-раздел-сайта). Ошибок быть не должно.
4. Откройте сайт через локальный веб-сервер и обновите страницу сочетанием `Ctrl + F5`.
5. Откройте вкладки «Дома», «Бани» и «Беседки».
6. Найдите изменённую карточку. Проверьте код, площадь, цену и главную фотографию.
7. Нажмите «Подробнее». Проверьте описание, преимущества и все картинки галереи.
8. Нажмите «Хочу такой же» и убедитесь, что форма расчёта открылась с правильным типом и параметрами.
9. Уменьшите окно браузера или откройте сайт на телефоне: важная часть фотографии не должна обрезаться.

Если весь раздел каталога показывает сообщение «Не удалось загрузить раздел», почти всегда повреждён JSON, повторяется `id` или указана неизвестная категория.

## Частые ошибки

- **После блока забыли запятую.** Между соседними проектами нужна запятая.
- **Поставили запятую после последнего блока.** Перед закрывающей `]` её быть не должно.
- **Использовали фигурные кавычки `“ ”`.** В JSON подходят только обычные двойные кавычки `"`.
- **Написали цену как `1 750 000 ₽`.** Нужно число `1750000`.
- **Написали площадь как `72,5`.** Нужно `72.5`.
- **Повторили `id`.** У каждого проекта должен быть свой `id`. Используйте только маленькие латинские буквы, цифры и дефисы.
- **Написали русские буквы в `id`.** Внешне похожие русская `с` и латинская `c` — разные символы и могут вызвать ошибку.
- **Ошиблись в категории.** Допустимы только `house`, `bath` и `gazebo`.
- **Переименовали фотографию, но не исправили `src`.** Имя и расширение должны совпадать полностью.
- **Использовали обратные слэши.** В JSON-пути нужен `/`, а не `\`.
- **Поставили планировку первой картинкой.** На карточке она будет обрезана. Первой должна быть фотография.
- **Вставили обычные двойные кавычки внутрь текста.** Лучше используйте русские кавычки `«ёлочки»`. Иначе внутреннюю кавычку придётся записывать как `\"`.
- **Удалили скрытый проект и потом захотели вернуть.** Лучше использовать `"published": false`, а не удаление.
