# Как добавлять и менять отзывы

[← Вернуться к списку инструкций](README.md)

## Что изменяет эта инструкция

Здесь настраивается раздел **«Отзывы наших клиентов»**. В каждом отзыве сайт показывает:

- короткую подпись с городом;
- текст отзыва;
- имя клиента;
- подпись о проекте;
- фотографию;
- подпись поверх фотографии.

Отзывы переключаются стрелками и автоматически через несколько секунд.

## Где находятся текст и фотографии

- Все отзывы: `content/reviews.json`.
- Новые фотографии отзывов рекомендуется хранить в папке `assets/reviews/`.

Если папки `assets/reviews/` ещё нет, создайте её при добавлении первой фотографии. Папка начнёт участвовать в публикации, когда в ней появится файл.

Название файла пишите маленькими латинскими буквами, без пробелов. Например:

```text
assets/reviews/ivanovy-skt-65.webp
```

В JSON используйте прямые слэши `/`. Не вставляйте путь с диском (`C:\...`), обратные слэши (`\`) или первый слэш перед `assets`.

## Как подготовить фотографию

Фотография отзыва показывается в горизонтальной рамке.

- рекомендуемый размер — **1500 × 1000 пикселей**;
- пропорции — **3:2**;
- лучший формат — **WebP**;
- можно использовать JPEG (`.jpg`);
- рекомендуемый вес — **до 500 КБ**.

Лучше использовать фотографию готового дома, бани, беседки или клиента на фоне объекта. Главный объект держите ближе к центру: сайт заполняет всю рамку и может немного обрезать края.

Внизу фотографии появляется тёмная подпись из поля `caption`. Не размещайте лица, номер дома или важную деталь у самого нижнего края — подпись может её закрыть.

Поле `alt` должно коротко описывать, что видно. Например: `Готовый дом семьи Ивановых в Медведево`. Не пишите `Фото клиента` или имя файла.

Перед публикацией фотографии и имени убедитесь, что клиент разрешил их использовать на сайте. Если полного имени публиковать нельзя, можно указать только имя или имя с первой буквой фамилии: `Анна И.`.

## Что означают поля

| Поле | Что писать |
| --- | --- |
| `id` | Уникальное служебное имя латиницей: `review-ivanovy-skt-65`. Только маленькие буквы, цифры и дефисы. |
| `label` | Короткая строка над отзывом, обычно `Отзыв · Город`. |
| `text` | Сам отзыв. Лучше 2–5 коротких предложений. |
| `author` | Имя клиента в том виде, который разрешено публиковать. |
| `role` | Короткая подпись, например `Дом по проекту СКТ-65`. |
| `image.src` | Путь к фотографии, например `assets/reviews/ivanovy-skt-65.webp`. |
| `image.alt` | Описание содержимого фотографии. |
| `caption` | Короткая подпись, которая появится внизу поверх фотографии. |
| `published` | `true` показывает отзыв, `false` скрывает его. |
| `example` | Служебная пометка демонстрационного текста. Посетитель её не видит. Для настоящего отзыва ставьте `false` или удалите строку. |
| `order` | Порядок отзывов. Меньшее число показывается раньше. |

Не меняйте `"schemaVersion": 1`.

## Как безопасно изменить существующий отзыв

1. Откройте `content/reviews.json` в редакторе кода, например Visual Studio Code.
2. Найдите отзыв по строке `"id": "..."` или по имени в поле `author`.
3. Меняйте только нужный текст справа от двоеточия.
4. Если меняете фотографию, сначала положите новый файл в `assets/reviews/`, затем исправьте `image.src`.
5. Не меняйте `id` у уже опубликованного отзыва.
6. Для настоящего отзыва убедитесь, что `example` равен `false`.
7. Сохраните файл и выполните проверку ниже.

Если в отзыве нужны кавычки, используйте русские кавычки `«ёлочки»`. Обычная двойная кавычка `"` внутри текста может сломать JSON, если её неправильно записать.

Текст каждого поля должен оставаться на одной строке в JSON. Не нажимайте Enter внутри кавычек с текстом отзыва.

## Как добавить новый отзыв

1. Получите разрешение клиента на публикацию текста, имени и фотографии.
2. Подготовьте фотографию и положите её в `assets/reviews/`.
3. В `content/reviews.json` найдите список `"items": [`.
4. Скопируйте целиком один существующий отзыв от `{` до соответствующей `}`.
5. Вставьте копию внутри списка `items`.
6. Поставьте запятую между соседними блоками. После последнего блока запятая не нужна.
7. Придумайте новый `id`, которого нет ни у одного отзыва, включая скрытые.
8. Замените все поля. Не оставляйте демонстрационный текст или чужое имя.
9. Поставьте `"example": false`.
10. Сначала можно поставить `"published": false`. После проверки замените значение на `true`.

## Как временно скрыть отзыв

Найдите нужный блок и замените:

```json
"published": true
```

на:

```json
"published": false
```

Отзыв исчезнет с сайта, но останется в файле. Чтобы вернуть его, снова поставьте `true`.

Это безопаснее, чем удалять весь блок. Не удаляйте отзыв только из-за временной просьбы клиента скрыть публикацию.

## Как изменить порядок

Поле `order` задаёт порядок:

```json
"order": 1
```

Отзыв с `order: 1` показывается первым, с `order: 2` — вторым. Используйте разные целые числа. Чтобы поменять два отзыва местами, поменяйте их числа `order`.

## Полный правильный пример файла

Ниже — полный рабочий пример `content/reviews.json`. Это образец структуры, а не команда удалить настоящие отзывы.

```json

  "schemaVersion": 1,
  "items": [
    {
      "id": "review-elena-skt-65",
      "label": "Отзыв · Йошкар-Ола",
      "text": "Постройка прошла спокойно и понятно. Команда заранее объяснила этапы, регулярно показывала ход работ и сдала дом в согласованный срок.",
      "author": "Елена",

        "alt": "Готовый каркасный дом Елены в Йошкар-Оле"
      },
      "caption": "Дом после завершения строительства",
      "published": true,
      "example": false,
      "order": 1
    },
    {
      "id": "review-alexander-skb-36",
      "label": "Отзыв · Медведево",
      "text": "Выбрали баню с комнатой отдыха и верандой. Все вопросы решали быстро, материалы привозили вовремя, результатом довольны.",
      "author": "Александр",
      "role": "Баня по проекту СКБ-36",
      "image": {
        "src": "assets/projects/bath/skb-36-cover.webp",
        "alt": "Готовая каркасная баня Александра в Медведево"
      },
      "caption": "Баня с верандой на участке клиента",
      "published": true,
      "example": false,
      "order": 2
    }
  ]

```

## Как проверить результат

1. Убедитесь, что файл сохранился как `reviews.json`, а не `reviews.json.txt`.
2. Проверьте, что фотография действительно добавлена и её имя совпадает с `image.src`, включая большие и маленькие буквы.
3. Проверьте JSON способом из раздела [«После изменения JSON пропал целый раздел сайта»](10-troubleshooting.md#после-изменения-json-пропал-целый-раздел-сайта). Ошибок быть не должно.
4. Откройте сайт через локальный веб-сервер и нажмите `Ctrl + F5`.
5. Перейдите в раздел «Отзывы наших клиентов».
6. Стрелками откройте каждый отзыв.
7. Проверьте город, текст, имя, подпись о проекте, фотографию и подпись на фотографии.
8. Убедитесь, что в тексте нет демонстрационных фраз и личных данных, которые клиент не разрешал публиковать.
9. Проверьте раздел в узком окне или на телефоне: важная часть фотографии не должна быть обрезана или закрыта подписью.

Если весь раздел показывает сообщение «Не удалось загрузить раздел», проверьте запятые, кавычки и повторяющиеся `id`.

## Частые ошибки

- **Опубликовали отзыв без согласия клиента.** Перед публикацией подтвердите разрешение на текст, имя и фотографию.
- **Оставили демонстрационный текст.** Для настоящего отзыва замените все поля и поставьте `"example": false`.
- **Вставили перенос строки внутрь текста.** В JSON текст между кавычками должен идти одной строкой.
- **Вставили обычную двойную кавычку внутрь отзыва.** Используйте `«ёлочки»`.
- **Повторили `id`** или использовали в нём русские буквы. Нужны уникальные маленькие латинские буквы, цифры и дефисы.
- **Фотография не пропорции 3:2.** Сайт обрежет края.
- **Важная деталь находится снизу.** Её может закрыть подпись `caption`.
- **Написали неправильный путь.** Правильно: `assets/reviews/file.webp` с прямыми слэшами.
- **Расширение не совпадает.** Если файл называется `.jpg`, нельзя написать `.webp`.
- **Регистр букв отличается.** На компьютере файл может открываться, а после публикации — нет.
- **Забыли запятую между отзывами** или оставили её после последнего блока.
- **Удалили отзыв вместо скрытия.** Ставьте `"published": false`, чтобы его можно было вернуть.
