# GitHub Desktop и публикация сайта

Эта инструкция объясняет, как без командной строки получить свежие файлы, сохранить изменения и отправить их на настоящий сайт.

Перед отправкой обязательно проверьте изменённый раздел через Live Server. После отправки в `main` изменения увидят посетители.

## Слова на экране простыми словами

| Слово или кнопка | Что это значит |
| --- | --- |
| **Git** | Система, которая запоминает изменения файлов и хранит историю. GitHub Desktop управляет ею вместо командной строки. |
| **GitHub Desktop** | Программа на компьютере для получения, проверки, сохранения и отправки изменений. |
| **GitHub** | Сервис в интернете, где хранится основная копия проекта. |
| **Repository** | Весь проект сайта и история его изменений. |
| **Current repository** | Проект, который сейчас открыт в GitHub Desktop. Здесь должен быть `stroikarkas`. |
| **Branch** | Отдельная версия проекта. Для обычного обновления нужна ветка `main`. |
| **Fetch origin** | Проверить, появились ли новые изменения на GitHub. Файлы на компьютере эта проверка сама не меняет. |
| **Pull origin** | Скачать найденные изменения в папку на компьютере. |
| **Changes** | Список файлов, которые изменились на компьютере. |
| **Summary** | Короткое описание вашей работы. |
| **Commit to main** | Создать подписанную точку сохранения на этом компьютере. |
| **Push origin** | Отправить точку сохранения на GitHub. |
| **origin** | Короткое название основной копии проекта на GitHub. |

**Commit** ещё не обновляет настоящий сайт. Обновление начинается только после успешного **Push origin**.

## Три правила безопасности

1. Всегда проверяйте, что выбраны проект `stroikarkas` и ветка `main`.
2. Перед началом получайте свежую версию через **Fetch origin** и **Pull origin**.
3. Перед коммитом просматривайте каждый файл в разделе **Changes**.

Не нажимайте **Discard changes**, **Reset**, **Force push** и не создавайте **fork**. Эти действия не нужны редактору сайта и могут удалить работу или создать лишнюю копию проекта.

## 1. Откройте правильный проект

Запустите GitHub Desktop.

В верхней части окна проверьте:

- **Current repository** — `stroikarkas`;
- **Current branch** — `main`.

Если там другой проект или другая ветка, остановитесь. Не переключайте варианты наугад — обратитесь к разработчику.

Если проекта нет в списке, используйте **File → Add local repository** и выберите существующую папку `stroikarkas`. Если правильной папки на компьютере ещё нет, выполните клонирование по инструкции [Начните отсюда](01-start.md#вариант-а-клонировать-проект).

## 2. Убедитесь, что не осталось незаконченной работы

Откройте вкладку **Changes** слева.

Если GitHub Desktop показывает **0 changed files** или **No local changes**, можно продолжать.

Если уже виден список файлов:

- вспомните, не осталась ли это ваша незаконченная работа;
- не снимайте галочки и не нажимайте **Discard changes**;
- если происхождение файлов непонятно, остановитесь и обратитесь к разработчику.

Сначала нужно разобраться с существующими изменениями, и только потом начинать новую задачу.

## 3. Получите свежую версию

1. Нажмите **Fetch origin** в верхней части окна.
2. Дождитесь окончания проверки.
3. Если кнопка сменилась на **Pull origin**, нажмите её.
4. Дождитесь окончания загрузки.

Если кнопка осталась **Fetch origin**, новых файлов на GitHub нет — у вас уже свежая версия.

Если появилось сообщение о конфликте, не выбирайте способ исправления самостоятельно. Остановитесь и откройте раздел [GitHub Desktop сообщает о конфликте](10-troubleshooting.md#github-desktop-сообщает-о-конфликте).

## 4. Измените и проверьте сайт

1. Откройте **Repository → Open in Visual Studio Code** или **Open in default editor**.
2. Измените только нужные файлы.
3. Сохраните каждый файл сочетанием `Ctrl+S`.
4. Запустите `index.html` через **Open with Live Server**.
5. Проверьте изменённый раздел на компьютере.

Двойной щелчок по `index.html` не заменяет Live Server: проекты и отзывы в таком режиме могут не загрузиться.

## 5. Просмотрите Changes

Вернитесь в GitHub Desktop. Слева появится список изменённых файлов.

1. Нажмите на имя каждого файла.
2. Справа посмотрите, что именно изменилось.
3. Зелёным обычно отмечены добавленные строки, красным — удалённые.
4. Проверьте, что в списке нет случайных или незнакомых файлов.

Если вы добавили изображение, в **Changes** должны быть видны и само изображение, и JSON-файл, в котором указан путь к нему.

Слева от каждого файла есть галочка. В коммит попадут только отмеченные файлы.

- Оставьте галочки только у файлов текущей задачи.
- Снятие галочки безопасно: файл останется на компьютере, но не попадёт в этот коммит.
- Не используйте **Discard changes**: эта команда убирает изменения из файла.

Если не понимаете, откуда появился файл, не включайте его в коммит и спросите разработчика.

## 6. Заполните Summary

В левом нижнем углу находится поле **Summary**. Коротко напишите, что изменили.

Хорошие варианты:

- `Добавлен новый проект дома`;
- `Обновлены фотографии стройки`;
- `Исправлен текст отзыва`;
- `Обновлена стоимость проекта СКТ-65`.

Не пишите просто `Правки` или `Изменения`: позже будет трудно понять, что произошло.

Поле **Description** заполнять необязательно.

## 7. Нажмите Commit to main

Ещё раз проверьте:

- выбран проект `stroikarkas`;
- выбрана ветка `main`;
- отмечены только нужные файлы;
- поле **Summary** заполнено;
- сайт проверен через Live Server.

После этого нажмите **Commit to main**.

Коммит — это точка сохранения только на вашем компьютере. Пока вы не нажали **Push origin**, GitHub и настоящий сайт ещё не изменились.

Если после коммита в **Changes** остались файлы, они не вошли в эту точку сохранения. Не нажимайте наугад. Проверьте, относится ли каждый файл к текущей задаче.

## 8. Нажмите Push origin

В верхней части окна нажмите **Push origin** и дождитесь окончания отправки.

Если отправка прошла успешно, кнопка снова станет **Fetch origin**, а GitHub Desktop покажет, что локальных изменений нет.

Если программа просит сначала получить новые изменения:

1. Нажмите **Fetch origin**.
2. Затем нажмите **Pull origin**, если такая кнопка появилась.
3. Если загрузка прошла без предупреждений, снова нажмите **Push origin**.
4. Если появилось слово **conflict** или кнопка **Force push**, остановитесь и обратитесь к разработчику.

Если GitHub Desktop предлагает создать fork, нажмите **Cancel**. Скорее всего, у учётной записи нет права записи в основной проект.

## Как изменения появляются на сайте

Для проекта уже настроена автоматическая публикация через GitHub Pages:

1. **Push origin** отправляет коммит в ветку `main` на GitHub.
2. GitHub Actions запускает задачу **pages build and deployment**.
3. GitHub Pages переносит свежие файлы на настоящий сайт.

Такой перенос разработчики называют «деплоем». В этой документации используется более понятное слово **публикация**.

Обычно публикация занимает около минуты, иногда — несколько минут.

### Как проверить публикацию

1. Откройте [страницу Actions проекта](https://github.com/SherlockD/stroikarkas/actions).
2. Найдите самую верхнюю задачу **pages build and deployment** для ветки `main`.
3. Жёлтый значок означает, что публикация ещё выполняется.
4. Зелёная галочка означает, что публикация закончилась.
5. Красный крест означает ошибку. Откройте задачу, запишите её название и сообщите разработчику.
6. После зелёной галочки откройте [настоящий сайт](https://stroy-karkas12.ru/).
7. Нажмите `Ctrl+F5`, чтобы браузер загрузил свежую версию.

Если изменения не видны, подождите ещё две-три минуты и снова нажмите `Ctrl+F5`. Затем используйте раздел [Изменения отправлены, но на сайте их нет](10-troubleshooting.md#изменения-отправлены-но-на-сайте-их-нет).

## Короткая памятка

До редактирования:

1. `Current repository` — `stroikarkas`.
2. `Current branch` — `main`.
3. В **Changes** нет старых непонятных файлов.
4. Нажать **Fetch origin**.
5. Если появилась кнопка **Pull origin**, нажать её.

После редактирования:

1. Проверить сайт через Live Server.
2. Просмотреть каждый файл в **Changes**.
3. Оставить галочки только у нужных файлов.
4. Заполнить **Summary**.
5. Нажать **Commit to main**.
6. Нажать **Push origin**.
7. Дождаться зелёной галочки в Actions.
8. Открыть настоящий сайт и нажать `Ctrl+F5`.

## Если ошибку заметили после публикации

Не пытайтесь удалять или переписывать старый коммит.

1. Исправьте данные в VS Code.
2. Проверьте исправление через Live Server.
3. Вернитесь в GitHub Desktop.
4. Просмотрите **Changes**.
5. Создайте новый **Commit to main** с понятным Summary.
6. Нажмите **Push origin**.

Новый правильный коммит безопасно исправит сайт, а история останется понятной.
