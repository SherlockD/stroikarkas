# Git и публикация сайта

[← Вернуться к списку инструкций](README.md)

Эта инструкция объясняет, как безопасно отправить готовые изменения на настоящий сайт.

Перед отправкой обязательно запустите сайт через Live Server и проверьте изменённый раздел. После отправки в ветку `main` изменения станут видны посетителям.

## Git простыми словами

Представьте, что папка сайта — это рабочая тетрадь:

- **Git** хранит историю тетради и позволяет увидеть, что изменилось.
- **GitHub** хранит общую копию тетради в интернете.
- **Ветка `main`** — основная версия, из которой публикуется сайт.
- **Коммит (`commit`)** — точка сохранения с коротким пояснением о сделанном изменении.
- **Пуш (`push`)** — отправка своих коммитов на GitHub.
- **Пул (`pull`)** — получение новых коммитов с GitHub.

Коммит сначала создаётся только на вашем компьютере. Настоящий сайт начнёт обновляться после успешной команды `git push origin main`.

## Что означают основные команды

| Команда | Простое объяснение |
| --- | --- |
| `git pull --ff-only origin main` | Скачать свежие изменения с GitHub, не создавая неожиданных объединений. |
| `git status --short` | Показать список изменённых и новых файлов. |
| `git diff` | Показать ещё не выбранные через `git add` изменения в существующих файлах. |
| `git add -- ...` | Выбрать конкретные файлы для ближайшего коммита. |
| `git diff --cached` | Ещё раз показать именно то, что войдёт в коммит. |
| `git commit -m "..."` | Создать точку сохранения на компьютере. |
| `git push origin main` | Отправить коммит на GitHub и запустить публикацию. |

## Главное правило

В начале работы сначала получайте свежую версию проекта. В конце добавляйте в коммит только те файлы, которые меняли сами.

Не используйте команды с `--force`, `reset --hard` и случайные команды из интернета. Они могут удалить работу или затереть изменения другого человека.

## 1. Откройте терминал в правильной папке

В VS Code выберите **Terminal → New Terminal** («Терминал → Новый терминал»).

Проверьте текущую папку:

```powershell
Get-Location
```

Путь должен заканчиваться на `stroikarkas`.

Проверьте ветку:

```powershell
git branch --show-current
```

Ожидаемый ответ:

```text
main
```

Если указана другая ветка или появилась ошибка, остановитесь и обратитесь к разработчику.

## 2. До редактирования получите свежую версию

Сначала убедитесь, что от прошлой работы ничего не осталось:

```powershell
git status --short
```

Если команда показала хотя бы один файл, пока не выполняйте `pull`. Откройте раздел [Git pull не выполнился](10-troubleshooting.md#git-pull-не-выполнился) и разберитесь с этими изменениями.

Если команда ничего не показала, выполните:

```powershell
git pull --ff-only origin main
```

Нормальные ответы:

- `Already up to date.` — у вас уже свежая версия;
- несколько строк о полученных файлах — Git скачал изменения другого человека.

Если Git отказался выполнять команду из-за ваших локальных изменений, не удаляйте их. Откройте раздел [Git pull не выполнился](10-troubleshooting.md#git-pull-не-выполнился).

Теперь можно менять файлы, сохранять их и проверять сайт через Live Server.

## 3. Посмотрите список изменений

После редактирования и проверки выполните:

```powershell
git status --short
```

Перед именем файла Git показывает обозначение:

- `M` — существующий файл изменён;
- `??` — появился новый файл;
- `A` — новый файл уже выбран для коммита.
- `D` — файл удалён. Если вы не собирались его удалять, остановитесь и спросите разработчика.

В списке должны быть только понятные вам файлы. Если появился незнакомый файл, не добавляйте его и спросите разработчика.

Чтобы увидеть изменения внутри существующих текстовых файлов, выполните:

```powershell
git diff
```

Строки с `-` удалены, строки с `+` добавлены. Если длинный список открылся в отдельном режиме, нажмите клавишу `q`, чтобы выйти.

Новые файлы со знаком `??` эта команда пока не показывает. Их имена уже видны в `git status --short`.

## 4. Выберите файлы для коммита

Используйте точные имена файлов. Например, если изменён только каталог проектов:

```powershell
git add -- 'content/projects.json'
```

Если одновременно добавлена фотография:

```powershell
git add -- 'content/projects.json' 'assets/projects/house/new-house.webp'
```

Замените `new-house.webp` на настоящее имя своего файла.

Пути в командах Git пишите через `/`. Кавычки оставляйте — они защищают пути с пробелами.

Не используйте `git add .`: эта короткая команда может незаметно добавить лишние файлы.

Проверьте выбранные файлы:

```powershell
git diff --cached
git status --short
```

В коммит должно попасть только то, что относится к вашей задаче.

Если выбрали лишний файл, уберите его из будущего коммита безопасной командой:

```powershell
git restore --staged -- 'путь/к/лишнему-файлу'
```

Эта команда только уберёт файл из списка для коммита. Сделанные правки останутся на компьютере.

## 5. Создайте коммит

Напишите коротко, что изменили. Например:

```powershell
git commit -m "Добавлен новый проект дома"
```

Другие хорошие примеры:

```powershell
git commit -m "Обновлены фотографии стройки"
git commit -m "Исправлен текст отзыва"
git commit -m "Обновлена стоимость проекта СКТ-65"
```

Сообщение должно описывать результат. Не пишите просто `Правки` или `Изменения`.

Если Git пишет `nothing to commit`, откройте раздел [Git пишет nothing to commit](10-troubleshooting.md#git-пишет-nothing-to-commit).

## 6. Отправьте изменения на GitHub

Выполните:

```powershell
git push origin main
```

При первой отправке Git может открыть браузер и попросить войти в GitHub:

1. Войдите именно в ту учётную запись, которой выдали доступ к проекту.
2. Разрешите приложению Git Credential Manager работать с GitHub, если появится такой запрос.
3. Вернитесь в VS Code и дождитесь завершения команды.

Не вводите пароль от GitHub в терминал и никому его не отправляйте. Современный вход обычно выполняется через браузер.

Успешная отправка обычно заканчивается строками, похожими на:

```text
main -> main
```

Для проверки выполните:

```powershell
git status
```

Нормальный итог:

```text
On branch main
Your branch is up to date with 'origin/main'.
nothing to commit, working tree clean
```

Если появились слова `rejected`, `403`, `Permission denied` или `Authentication failed`, ничего не отправляйте принудительно. Найдите эту ошибку в [памятке по проблемам](10-troubleshooting.md).

## Как изменения появляются на сайте

Сайт не нужно вручную копировать на сервер. Для проекта уже настроена автоматическая публикация через GitHub Pages:

1. Вы выполняете `git push origin main`.
2. GitHub получает изменения в ветке `main`.
3. GitHub Actions запускает задачу **pages build and deployment**.
4. GitHub Pages публикует файлы на сайте.

Обычно это занимает около минуты, иногда — несколько минут.

### Как проверить публикацию

1. Откройте [страницу Actions проекта](https://github.com/SherlockD/stroikarkas/actions).
2. Найдите самую верхнюю задачу **pages build and deployment** для ветки `main`.
3. Жёлтый значок означает «ещё выполняется».
4. Зелёная галочка означает «готово».
5. Красный крест означает ошибку — откройте задачу, сделайте снимок экрана и отправьте разработчику.
6. После зелёной галочки откройте [настоящий сайт](https://sherlockd.github.io/stroikarkas/).
7. Нажмите `Ctrl+F5`, чтобы браузер загрузил свежую версию, а не сохранённую старую копию.

Если изменения всё равно не видны, подождите ещё две-три минуты и снова нажмите `Ctrl+F5`. Затем пройдите проверку [Изменения отправлены, но на сайте их нет](10-troubleshooting.md#изменения-отправлены-но-на-сайте-их-нет).

## Короткая памятка на каждый раз

До изменения:

```powershell
git branch --show-current
git status --short
git pull --ff-only origin main
```

После `git status --short` переходите к `git pull` только тогда, когда список пуст.

После изменения и локальной проверки:

```powershell
git status --short
git diff
git add -- 'точный/путь/к/изменённому-файлу'
git diff --cached
git commit -m "Коротко описано изменение"
git push origin main
git status
```

Строки `точный/путь/к/изменённому-файлу` и `Коротко описано изменение` — это подсказки. Замените их своими значениями, не копируйте буквально.

## Если ошибку заметили после публикации

Не пытайтесь удалять историю Git.

1. Исправьте данные в обычном файле.
2. Снова проверьте сайт через Live Server.
3. Создайте ещё один коммит с исправлением.
4. Отправьте его обычной командой `git push origin main`.

Новая правильная версия заменит ошибочную на сайте, а история останется понятной.
